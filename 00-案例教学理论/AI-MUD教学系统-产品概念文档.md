# AI-MUD 教学系统：基于对话的情境学习平台

## 核心理念

**从预设剧情到生成式叙事，从选择题到自由对话，从固定路径到个性化学习旅程。**

---

## 一、系统本质

### 1.1 双轨驱动机制

```
┌──────────────────────────────────────────────┐
│                学生交互层                      │
│         （自然语言输入，无菜单限制）            │
└─────────────────┬────────────────────────────┘
                  │ 学生的文字输入
                  │
    ┌─────────────▼─────────────┐
    │                           │
    │    预设故事线              │    AI 实时生成
    │  （教学目标约束）      ◄───┼───►  （剧情推进）
    │                           │
    └─────────────┬─────────────┘
                  │
    ┌─────────────▼─────────────┐
    │      上下文记忆系统         │
    │  保存所有对话、决策、状态   │
    └─────────────┬─────────────┘
                  │
┌─────────────────▼────────────────────────────┐
│              教师监控层                       │
│   看到每个学生的完整对话记录和知识点覆盖      │
└──────────────────────────────────────────────┘
```

**核心特点：**

1. **预设故事线** = 教学大纲 + 关键知识点 + 世界规则
   - 不是具体的对话和情节
   - 是目标、约束、底层逻辑

2. **AI 实时生成** = 根据学生输入 + 故事线约束 + 上下文记忆
   - 每次回应都独一无二
   - 但永远在教学目标的框架内

3. **上下文记忆** = 学生的完整学习轨迹
   - 每个决策都有记录
   - 每个对话都是后续推进的依据
   - 知识点覆盖率实时追踪

4. **教师视角** = 30 个学生，30 条不同的故事线
   - 不是看"对错"，而是看"路径"
   - 发现意想不到的学习方式
   - 识别需要课堂讨论的典型案例

### 2.2 核心组件详解

#### A. 对话引擎（Dialogue Engine）

**职责：** 生成 AI 的回应，推进剧情

**输入：**
- 学生的文字输入
- 当前场景状态
- 完整对话历史
- 教学目标约束

**输出：**
- AI 生成的叙事文本
- 状态变化
- 触发的知识点

**实现示例（提示词结构）：**

```python
SYSTEM_PROMPT = """
你是一个职业教育情境模拟系统的 Game Master（GM）。

{world_setting}

【当前场景】

场景目标：{learning_objectives}
# 例如：学生需要掌握"运输方式选择"的决策框架

【NPC 角色】
{npc_profiles}
# 张雷：暴躁主管，38岁，16年行业经验，刀子嘴豆腐心...

【游戏状态】
```

#### B. 知识守护系统（Knowledge Guardian）

**职责：** 确保 AI 生成的内容符合行业知识，不会误导学生

**机制：**

1. **知识库匹配**
   ```python
   # 当 AI 提到专业概念时，自动校验
   if "厢式货车" in ai_response:
       specs = knowledge_base.get("厢式货车")
       # 检查 AI 说的载重、容积是否正确
       validate(ai_response, specs)
   ```

2. **数值一致性检查**
   ```python
   # 如果之前说了"货物 60 立方米"
   # 后面 AI 不能突然说"50 立方米"
   consistency_checker.validate(ai_response, context)
   ```

3. **禁止清单**
   ```python
   # AI 不能随意编造的内容
   forbidden_topics = [
       "公司财务状况",  # 没有设定
       "客户的私人信息",  # 隐私问题
       "明天的工作安排"  # 超出场景范围
   ]
   ```

4. **专家审核机制**
   ```python
   # 如果 AI 生成了不确定的内容
   if uncertainty_score > 0.7:
       flag_for_expert_review()
       # 使用备用的保守回应
   ```

#### D. 教学目标追踪器（Learning Objective Tracker）

**职责：** 实时监控学生是否覆盖了关键知识点

**机制：**

```python
class LearningObjectiveTracker:
    def __init__(self, scene_objectives):
        self.objectives = scene_objectives
        # 例如：
        # {
        #   "信息收集": {
        #     "必要性": "critical",
        #     "触发条件": ["查看订单", "去仓库", "询问他人"],
        #     "权重": 0.25
        #   },
        #   "天气风险评估": {
        #     "必要性": "important",
        #     "触发条件": ["查看天气预报", "询问天气"],
        #     "权重": 0.15
        #   }
        # }
    
    def analyze_turn(self, student_input, ai_response, state_changes):
        """分析本轮对话触发了哪些知识点"""
        triggered = []
        
        # 基于关键词匹配
        if "天气" in student_input or "下雨" in student_input:
            triggered.append("天气风险评估")
        
        # 基于行为模式
        if state_changes.get("location") == "warehouse":
            triggered.append("信息收集")
        
        # 基于 AI 标记
        if "knowledge_triggered" in ai_response:
            triggered.extend(ai_response["knowledge_triggered"])
        
        return triggered
    
    def get_coverage_rate(self, session_context):
        """计算知识点覆盖率"""
        covered = session_context["knowledgeCoverage"]
        total = len(self.objectives)
        covered_count = sum(1 for k, v in covered.items() if v["covered"])
        
        return {
            "total": total,
            "covered": covered_count,
            "rate": covered_count / total,
            "missing": [k for k, v in covered.items() if not v["covered"]]
        }
    
    def should_give_hint(self, session_context):
        """判断是否需要给提示"""
        coverage = self.get_coverage_rate(session_context)
        turns = session_context["meta"]["totalTurns"]
        
        # 如果玩了 20 轮还没触碰某个关键知识点
        if turns > 20 and coverage["rate"] < 0.5:
            return True, coverage["missing"][0]
        
        return False, None
```

## 五、与传统 RPG 方案的对比

### 5.1 核心差异

| 维度 | 预设剧本 RPG | AI-MUD |
|------|-------------|---------|
| **交互方式** | 点击选项 | 自然语言输入 |
| **内容** | 完全预写好 | AI 实时生成 |
| **自由度** | 有限分支（5-20条） | 无限可能 |
| **重玩价值** | 探索不同分支 | 每次都不同 |
| **开发成本** | 每场景 6-70h | 每场景 2-4h（写规则） |
| **NPC** | 固定台词 | 真实对话 |
| **意外性** | 设计者预设 | 学生创造 |
| **评估方式** | 路径追踪 | 知识点覆盖 |

### 5.2 技术成熟度对比

**预设剧本 RPG：**
- ✅ 技术成熟，100% 可控
- ✅ 内容质量有保证
- ✅ 成本可预测
- ⚠️ 内容创作工作量大
- ⚠️ 学生自由度受限

**AI-MUD：**
- ✅ 内容生成成本低
- ✅ 学生自由度高
- ✅ 每次体验不同
- ⚠️ AI 可能偏离目标（需要护栏）
- ⚠️ 知识准确性需要验证
- ⚠️ 评估体系更复杂

### 5.3 混合方案（推荐）

**阶段 1：预设 RPG（已设计）**
- 用于基础知识学习
- 学生熟悉系统操作
- 教师验证教学设计

**阶段 2：AI-MUD（进阶）**
- 用于综合能力训练
- 学生自由探索
- 培养应变能力

**结合使用：**
```
学期初（1-4周）
└─ 预设 RPG 场景 1-3
   学习基础决策框架

   自由应用所学知识

学期末（11-16周）
└─ 混合场景
   关键决策点用预设（确保知识点覆盖）
```

## 七、风险与应对

### 7.1 核心风险

**风险 1：AI 偏离教学目标**

**案例：**
```
学生："我能不能辞职不干了？"
AI："你递交了辞职信，开始找新工作..."
（完全偏离了学习目标）
```

**应对：**
```python
# 在提示词中加入强约束
"""
如果学生的行为明显偏离场景（如辞职、打架、离题太远），
不要直接满足，而是用 NPC 引导回来：

示例：
学生："我不想干了"
张雷："你才来一个月就想走？连这点小事都处理不了，
       以后去哪儿都一样。先把手上的事做完再说。"

（让学生感受到"逃避"的后果，但保持游戏继续）
"""
```

**风险 2：AI 给出错误的专业知识**

**案例：**
```
学生："厢式货车能装多少？"
AI："大概 100 立方米"
（实际是 40 立方米，AI 编造了）
```

**应对：**
```python
# 知识守护系统
def validate_professional_knowledge(ai_response):
    # 提取 AI 说的数字和专业术语
    entities = extract_entities(ai_response)
    
    for entity in entities:
        if entity.type == "vehicle_spec":
            # 从知识库查询正确数据
            correct_data = knowledge_base.get(entity.value)
            
            # 如果 AI 说的不对
            if not matches(entity.data, correct_data):
                # 替换为正确数据
                ai_response = replace(ai_response, entity, correct_data)
                
                # 标记警告
                flag_warning("AI gave incorrect specs")
    
    return ai_response
```

**风险 3：学生"玩"但没学**

**案例：**
学生一直在和 NPC 闲聊，没有推进任务。

**应对：**
```python
# 时间压力机制
if session.turns > 20 and session.knowledge_coverage < 0.3:
    # AI 引入紧迫感
    inject_event("张雷走过来：'怎么还没搞定？快点！'")

# 知识点引导
if "天气风险评估" not in session.covered_knowledge:
    if session.turns > 10:
        # NPC 提醒
        inject_hint("小王：'诶对了，今天天气怎么样？'")
```

### 7.2 成本风险

**AI API 费用可能很高**

**估算（基于 GPT-4）：**
- 每轮对话：约 2000 tokens（1000 输入 + 1000 输出）
- 费用：约 $0.06 per turn
- 一个学生完成一个场景：约 20 轮
- 单场景成本：$1.2
- 30 个学生：$36
- 10 个场景：$360/学期

**应对策略：**
1. 使用更便宜的模型（GPT-3.5 或国产大模型）
2. 优化提示词，减少 token 消耗
3. 对关键对话使用 GPT-4，其他用便宜模型
4. 向学生收费（每学期 50-100元）

**时机：** AI 技术刚好成熟，教育数字化转型在推进
**壁垒：** 先发优势 + 内容积累 + 数据积累

### 下一步

你现在可以选择：

1. **先做预设 RPG**（风险低，更快见效）
   - 用之前设计的方案
   - 3个月可以上线
   - 验证教学模式

2. **直接做 AI-MUD**（创新性强，但风险高）
   - 做最小原型验证
   - 技术挑战大
   - 如果成功，竞争力强

3. **两条腿走路**（推荐）
   - Phase 1: 预设 RPG（验证市场）
   - Phase 2: 引入 AI 增强
   - Phase 3: 完全 AI-MUD
